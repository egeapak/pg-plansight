# Integration Tests

This directory contains integration tests for pg-plansight that use testcontainers to test against a real PostgreSQL database.

## Overview

The integration tests in `integration_test.rs` verify that the log parser correctly handles real PostgreSQL logs generated by the `auto_explain` extension. These tests:

1. Spin up a PostgreSQL container using testcontainers
2. Enable and configure the `auto_explain` extension
3. Execute various SQL queries (simple SELECTs, JOINs, aggregates)
4. Capture the PostgreSQL logs containing query plans
5. Parse the logs using our log parser
6. Verify that the parsed data is correct

## Requirements

- **Docker**: These tests require Docker to be installed and running
- **Docker socket**: The Docker socket must be accessible (typically at `/var/run/docker.sock`)
- **Network access**: The tests need to pull the PostgreSQL Docker image

## Running the Tests

Since these tests require Docker, they are marked with `#[ignore]` by default and won't run during normal test execution.

### Run only the integration tests

```bash
cargo test --test integration_test -- --ignored
```

### Run all tests including integration tests

```bash
cargo test --test integration_test -- --include-ignored
```

### Run from the workspace root

```bash
# Run integration tests only
cargo test -p pg-plansight-core --test integration_test -- --ignored

# Run all core tests including integration tests
cargo test -p pg-plansight-core -- --include-ignored
```

## Test Cases

### `test_auto_explain_simple_query`
Tests basic SELECT query with a WHERE clause to verify simple query plan parsing.

### `test_auto_explain_join_query`
Tests JOIN queries with aggregation to verify complex query plan parsing.

### `test_auto_explain_aggregate_query`
Tests queries with GROUP BY and aggregate functions (COUNT, SUM, AVG).

### `test_parser_handles_multiple_queries`
Tests that the parser correctly handles multiple queries in sequence from the same log stream.

## Troubleshooting

### Docker not available
If you see an error like `Socket not found: /var/run/docker.sock`, ensure Docker is installed and running:

```bash
docker ps
```

### Permission denied on Docker socket
On Linux, you may need to add your user to the docker group:

```bash
sudo usermod -aG docker $USER
```

Then log out and back in for the changes to take effect.

### Tests timing out
If the tests are timing out, Docker might be slow to pull the PostgreSQL image. You can pre-pull it:

```bash
docker pull postgres:16-alpine
```

## CI/CD Integration

In CI/CD environments, you have two options:

1. **Skip integration tests** (default behavior): Run `cargo test` normally and these tests will be ignored
2. **Enable integration tests**: Ensure Docker is available in your CI environment and run with `--include-ignored`

Example GitHub Actions workflow:

```yaml
- name: Run tests
  run: cargo test

- name: Run integration tests
  run: cargo test -- --ignored
  if: runner.os == 'Linux'  # Only run on Linux where Docker is typically available
```
