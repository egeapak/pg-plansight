# pg_loganalyze — cross-version benchmarks (PG13–18)

Generated by the testcontainers harness (`crates/bench-harness`) against images
built per major by `crates/pg_extension/docker/Dockerfile.bench`. Each run loads a
50 000-row synthetic `orders` table and measures, for `capture_mode = off`
(baseline) vs `hook` (default async, `sample_rate=1`, `track_io` on):

- **point** — `SELECT * FROM orders WHERE id = $1` latency (OLTP),
- **olap** — `SELECT customer_id, count(*), avg(amount) … GROUP BY` latency,
- **tps** — point queries over a fixed window (high-throughput), hook ÷ baseline,
- **render** — the per-phase hot-path profiler (`loganalyze_capture_timings()`):
  ns spent in the `EXPLAIN` render, and `consume` = ring-push.

## Results

| PG | point off→hook | OLAP off→hook | throughput (hook/base) | render | ring-push |
|----|----------------|---------------|------------------------|--------|-----------|
| 13.23 | 0.200 → 0.223 ms (**+11%**) | 16.74 → 20.43 ms (**+22%**) | **93%** | ~25.6 µs | ~1.1 µs |
| 14.23 | 0.205 → 0.222 ms (**+9%**)  | 16.99 → 20.57 ms (**+21%**) | **93%** | ~26.2 µs | ~1.1 µs |
| 15.18 | 0.197 → 0.221 ms (**+12%**) | 16.81 → 20.71 ms (**+23%**) | **89%** | ~26.2 µs | ~1.2 µs |
| 16.14 | 0.202 → 0.212 ms (**+5%**)  | 17.47 → 21.30 ms (**+22%**) | **88%** | ~42.7 µs | ~2.3 µs |
| 17.10 | 0.211 → 0.206 ms (**~0%**)  | 16.48 → 20.41 ms (**+24%**) | **87%** | ~32.9 µs | ~1.3 µs |
| 18.4  | 0.210 → 0.219 ms (**+4%**)  | 15.53 → 19.70 ms (**+27%**) | **87%** | ~30.1 µs | ~1.3 µs |

Single-run numbers over a TCP socket (so point-query deltas are partly noise —
the network round-trip dominates a 0.2 ms query); treat them as order-of-magnitude.

## What the numbers say

- **Capture works on every major 13–18 at runtime** — not just compile. PG13
  exercises the `InstrAlloc` two-arg cfg branch; PG18 confirms the hook is correct
  despite the upstream `ExecutorStart` change (pgrx 0.18.1 binds it `void`).
- **OLAP overhead is ~21–27%**, dominated by `INSTRUMENT_TIMER` accounting *during
  execution* (not our render) — `sample_rate` is the lever to amortize it.
- **High-throughput cost is ~7–13%** (hook keeps 87–93% of baseline TPS) — the
  per-query render + ring-push on top of a 0.2 ms query.
- **Render is the hot path** (25–43 µs) and is irreducible (explain.c formatting
  carrying per-node `actual time`). The reusable render context + adaptive
  StringInfo prealloc keep it from being worse; `track_settings=off` shaves the
  ~5–7 µs `get_explain_guc_options` GUC scan. Ring-push is ~1–2 µs.

## Reproduce

```bash
# all majors (each image built then removed to bound disk):
scripts/bench_versions.sh

# a subset:
scripts/bench_versions.sh "16 18"

# behind a TLS-inspecting proxy / to dodge Docker Hub pull limits:
EXTRA_CA=path/to/ca-bundle.crt \
POSTGRES_IMAGE=public.ecr.aws/docker/library/postgres \
RUST_IMAGE=public.ecr.aws/docker/library/rust \
  scripts/bench_versions.sh
```

The harness also prints the live per-phase profile via `loganalyze.profile` +
`loganalyze_capture_timings()`, usable standalone on any running instance.
